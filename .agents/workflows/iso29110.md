# ISO 29110 Document Update Workflow

## When Starting New Work
1. Check `docs/iso29110/SI/requirements_spec.md` — is the requirement documented?
2. Check `docs/iso29110/SI/software_design.md` — is the design documented?
3. If not → add entries BEFORE writing code

## When Finishing Work
1. Update `docs/iso29110/SI/test_report.md` with test results
2. Update `docs/iso29110/PM/progress_status.md` with activity log
3. If scope changed → add to `docs/iso29110/PM/change_request.md`

## When Making Decisions
1. Record in `docs/iso29110/PM/meeting_records.md`

## When Releasing
1. Add entry to `docs/iso29110/SI/release_notes.md`
2. Update project plan milestone status in `docs/iso29110/PM/project_plan.md`

## Document Map

```
docs/iso29110/
├── PM/                              # Project Management
│   ├── project_plan.md              # WBS, milestones, risks
│   ├── progress_status.md           # Activity log
│   ├── change_request.md            # Scope changes
│   └── meeting_records.md           # Decisions
└── SI/                              # Software Implementation
    ├── requirements_spec.md         # REQ-xxx requirements
    ├── software_design.md           # Architecture & design
    ├── test_cases.md                # UT/IT/ST/BT test definitions
    ├── test_report.md               # Test execution results
    └── release_notes.md             # Version history
```
